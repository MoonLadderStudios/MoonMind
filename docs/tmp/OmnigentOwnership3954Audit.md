## Persisted-data disposition and cutover

**No table or field removal is justified in this change.** `api_service/db/models.py` contains 29 `omnigent_*` tables; all 29 remain. Their read/write families above cover:

- bridge sessions/events; canonical sessions, turn attempts, observations, commands, reconciliation decisions, chat aliases and cleanup authority;
- policies, versions and events; Agent Profiles, versions, audit events, usage and upstream projections;
- OAuth host bindings/leases and host auth profiles;
- execution plans, runtime bindings, host bindings/leases v2, credential runtimes/binding sets, harness catalog snapshots/trust and execution-plan usages.

No database migration, credential deletion, historical artifact rewrite, workflow/activity signature change, or durable payload conversion is introduced. The removed download name could not be dispatched: the canonical resource matcher already won before the additional native classifier. Existing `session_file` readers and retained artifact IDs remain valid. Existing receipts from speculative native operations stay readable; those operations receive an explicit route denial on a fresh request, never a replayed success that would authorize another unsupported mutation.

Deploy the API containing the closed allowlist before considering this request boundary effective; an older API replica still has its old admission behavior. Workers and already-running workflows keep their existing payloads and side-effect owners. This change does not add or alter worker replay semantics. Upstream remains at the same gitlink. Failed browser requests adapt by using the verified native surface or reporting compatibility review; they cannot reach an unrestricted proxy or direct upstream URL.
